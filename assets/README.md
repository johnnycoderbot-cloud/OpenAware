# Visual assets

`app-concept.png` is an AI-generated planning illustration requested by the project owner. It shows an earlier working title (Desktop AI), illustrative trading data, synthetic camera views, and proposed computer-action controls. It is not a screenshot of a shipped app or evidence of integration performance.

Original OpenAware documentation and this illustration are offered under the repository's MIT license to the extent applicable. Product names/logos depicted remain the property of their respective owners; no affiliation or endorsement is implied. No real desktop, personal camera feed, account, or credentials are shown.

`prototype-v0.1.png` preserves the earlier prototype interface for comparison with the generated concept.

`prototype-desktop.png` is an actual Electron screenshot generated by `tests/desktop.spec.ts` with an animated synthetic canvas and an explicitly mocked LM Studio-compatible fixture. It contains no personal feed or credential. Responses and timing belong to the test fixture and are not a real model benchmark.

`prototype-desktop-multisource.png` shows the v0.3.0 Electron interface at 1440×960 with synthetic demo/camera previews. `prototype-desktop-compact.png` shows the same fixture at 1024×720. Each source, assistant, activity and Video memory view is a direct pane with one frame/header and compact controls. Two desktop panes start side by side; extra feeds form rows above Video memory. Default feed heights fit video proportions with separate footers. Assistant/activity retain the 75%/25% sidebar split; Operator remains in navigation. The fixtures cover movement, resizing, compact containment and Video memory scrolling. They do not establish real camera/monitor capture, real model throughput or sources restored automatically. All populated identities/content are synthetic.

Version 0.2.2 introduced movable/resizable panes; v0.2.3 introduced the flat workspace. Version 0.2.4 retained Operator navigation, fitted default feeds to video proportions and added the lower New pane. Version 0.3.0 fills that pane with Video memory and adds sampled local temporal workflows. The visual regression regenerates these images; regeneration is not evidence that a user's live monitors are connected. Consult the [v0.3 implementation ledger](../.omx/logs/implementation-v0.3.md) for current local verification and pending publication gates. The [v0.2.4](../.omx/logs/implementation-v0.2.4.md) and [v0.2.3](../.omx/logs/implementation-v0.2.3.md) ledgers preserve earlier layout checks. The separate controlled native-window regression is described in the [v0.2.1 implementation ledger](../.omx/logs/implementation-v0.2.1.md).

`openaware-icon.svg`, `openaware-icon.png`, and `openaware-icon.ico` are the original OpenAware blue eye/O brand assets. The native tray uses matching raster PNG representations bundled in application code at 16, 20, 24, 32, 48, and 64 px; the ICO supplies Windows app/installer sizes through 256 px. These are ordinary logo assets, with no captured screen content.
