# OpenAware v0.3.0 local-workflow developer prototype

This implementation extends the desktop application against the full [release roadmap](roadmap.md). Version 0.3.0 adds local temporal observations, semantic alert rules, caption search, asynchronous historical summaries and opt-in CLI access. These sampled, bounded workflows use the existing LM Studio/Ollama adapters. They require no VSS server and contain no copied NVIDIA implementation, models or containers. Each source, chat, activity and Video memory view remains an independent pane on one flat workspace. Two monitor panes start side by side; three or four desktop panes use two-column rows, with cameras below. Operator retains its separate page and per-step native approval. The unsigned Windows package has been built and inspected locally; public source/tag, exact-commit CI and installer publication remain pending.

## Implemented boundary

- Electron desktop with a sandboxed renderer and a narrow, validated preload bridge; supervised awareness service over private process IPC.
- One workspace with source, assistant, activity and Video memory views directly on a single board. Default feed sizing follows uncropped video proportions, with a separate header and footer. Additional monitor rows grow into the lower area above Video memory. Assistant/activity retain the default 75%/25% sidebar split. Operator remains a separate page in the top navigation, which also includes compact Add source, Start watching and Reset controls, with Stop always available. Each pane has a drag handle and an Arrange icon menu; horizontal/vertical dividers resize it. Reset, source-list changes and returning to Overview restore the default arrangement. Live sources retain their connection when panes move or resize. Configuration, masks, source scope and evidence age remain available. Current asset screenshots show the v0.3.0 renderer with synthetic sources and mock model responses.
- Up to four explicit synthetic demo, camera, OBS virtual-camera, monitor, or window sources with continuous local previews. Capture starts only after selection; Stop releases owned tracks and invalidates inference.
- Black privacy rectangles on analysis images, separate preview/analysis age, bounded inference scheduling, and memory-only observations/conversation/events. Temporal monitoring retains up to three chronological masked frames per source spanning at most four seconds, with a fresh newest frame at dispatch. Observations show the analyzed interval, frame count and age; sampled images do not establish native continuous-video understanding.
- Local LM Studio and Ollama model discovery, explicit selection, visible synthetic vision probe, and source-grounded analysis/conversation. Local-only endpoints and ephemeral tokens; no cloud fallback.
- Independent deterministic motion events and acknowledgement.
- Up to eight semantic rules with explicit source scopes and revisioned model evidence. Two distinct matching observations at least two seconds apart qualify for an alert, with a 30-second cooldown. Uncertain, malformed, stale or mismatched evidence does not alert. Semantic alerts appear in activity/Event log and do not create or authorize Operator plans.
- Video memory searches caption words locally with source and capture-time filters. Asynchronous historical summaries use the newest complete caption subset fitting 25 records and 32,000 serialized characters, send text only to the selected model, and display their source/time scope, model and queued/running/completed/error state. A single-source scope excludes captions that also cite another source. No raw video recording or vector database is added.
- Opt-in `--enable-cli` access through a private authenticated loopback listener and an OpenAware CLI. Source builds emit `dist/cli.cjs`; the locally built package bundles it at `resources/cli.cjs`. Reserved Stop admission remains available when ordinary CLI calls fill the normal concurrency limit. The command whitelist cannot acquire sources, inject frames, select a provider/model, approve native input or execute shell commands. The [local video workflow guide](local-video-workflows.md) and [portable skill](../skills/openaware-video-workflows/SKILL.md) document its command surface.
- Observer and Operator AI roles sharing the selected model. Operator proposes up to eight typed steps; a Windows native review checks each step. Keyboard targets must be on the selected monitor; masked sources, changed displays/windows/screens, stale/expired plans, replay, and Stop revoke input.
- Background mode hides the dashboard without replacing the current renderer or restarting capture. Tray Show, Stop, and Quit remain available; an explicit background preference determines whether closing the window hides it or quits. `--background` and `--headless` start idle with no selected feeds in an interactive Windows desktop session.

The experimental input broker compares unchanged full-monitor thumbnails downsampled to at most 1024 px across native approval, and requires fresh inspection plus stable native window and display identities. It does not compare every physical pixel or certify a model's interpretation. Moving or animated screens may refuse execution. Actual input reports that Windows accepted events; it does not claim the application task succeeded. Stop cannot undo a sent event. Native effects, focus restoration, and mixed-DPI placement remain unverified on real applications.

## Run and configure

1. Install Node.js 24 or later and run `npm ci`, then `npm start` from the repository.
2. For a live screen, click **Add source**, choose **Monitor**, select the screen, then click **Connect source** in the dialog. The selected preview starts as the source is added; no separate pane connection step is needed. Repeat for a second monitor. **Window** captures a chosen application; **Demo** is synthetic content only. Live preview needs no model and does not require **Start watching**.
3. Start your local model server: LM Studio normally uses `http://127.0.0.1:1234`; Ollama normally uses `http://127.0.0.1:11434`.
4. In Connections, discover models, select a vision-capable model, and run the displayed synthetic test. Click **Start watching** for AI monitoring only after verified readiness. This step is separate from connecting a live preview.
5. In Connections, choose **Temporal monitoring** and add semantic rules with explicit source scopes if needed. Use **Video memory** to search captions by source/time or request **Summarize history**. Summaries describe retained history, not the current desktop. Alerts do not run computer actions.
6. Use **Sources** to choose connected feeds for each question. Operator planning needs a live selected monitor and verified local model. Native action review is per step; the emergency shortcut is Ctrl+Shift+F12 if available.
7. Click **Background** to continue the configured session with the dashboard hidden. Tray **Show OpenAware** preserves that preference; click **Window mode** to clear it. Tray Stop releases feeds and pending authority; Quit exits. See [background mode](background-mode.md).

Configuration, tokens, and history are memory only. Neither launch flag selects a source, binds a model, starts monitoring, nor restores an earlier session. Native actions continue to require interactive approval for every step.

Pane positions and sizes are temporary for the current Overview view. Global Reset, changing the source list, or returning to Overview restores defaults: two monitor panes side by side, three or four desktop panes in two-column rows, camera panes below, and Video memory under the fitted feed area. Added monitor rows use more of the lower space. Each source has separate header/footer controls around its uncropped preview. The same board scrolls when a custom arrangement exceeds the available space; compact windows use a vertical pane order. There are no parent feed containers to move separately. The fixed global Stop remains available regardless of arrangement. The assistant uses a conventional chat history and compact composer; each source's settings control holds AI analysis, motion alerts and privacy masks. The prototype limits simultaneous sources to four in total.

After a source build, launch `node_modules/.bin/electron.cmd . --enable-cli` to enable the local CLI, then run `node dist/cli.cjs --help`. The locally built package supports `OpenAware.exe --enable-cli`, with Node.js 24 or later executing `resources/cli.cjs`. The installer has been inspected by extraction; its installation and shortcuts have not been exercised. Adding `--background` starts an idle tray session. CLI access does not restore sources or bypass native action approval.

## Evidence and remaining gates

The [v0.3 implementation ledger](../.omx/logs/implementation-v0.3.md) records strict TypeScript, 147 passing unit/integration tests, the production build and the unsigned Windows x64 package. Installer extraction confirms the application and external CLI match the tested unpacked build. Independent source review approved the runtime and CLI after summary admission and saturated Stop handling were corrected. Final packaged desktop acceptance is tracked in that ledger; local checks do not establish public release or exact-commit CI success.

Direct synthetic tests on this computer found correct single-image recognition in about 18–20 seconds with the current local Ollama model. A cold probe reached 20 seconds; a three-image temporal request and a historical text summary each reached 60 seconds. This model has not demonstrated useful continuous monitoring, real desktop/camera interpretation or semantic rule accuracy.

Background caption and historical summary jobs allow 60 seconds. Synthetic probes, current chat and Operator allow 20 seconds; current chat/Operator evidence must also remain within the 15-second completion freshness boundary. The newest frame must be within five seconds at dispatch. Delayed background captions can remain historical up to 65 seconds of newest-frame age, but semantic rule evidence older than 15 seconds is unknown and cannot alert. Preview continues independently of these deadlines. Slower models may still time out; no automatic cloud fallback is added.

Source checks exercise strict TypeScript compilation, unit/integration contracts, synthetic Electron workflows, hidden capture and inference continuity, desktop visibility, headless idle startup, close behavior, and Quit. The production tray test inspects the real menu and invokes installed Show/Stop/Quit callbacks; it does not simulate physical tray clicks. Visual fixtures use the actual Electron renderer with synthetic content. Version 0.2.1 adds a controlled regression using two native windows containing only generated test content, to exercise real Electron display acquisition without personal screen capture. Its reproduction, results, final counts, and packaged checks are recorded in the [v0.2.1 implementation ledger](../.omx/logs/implementation-v0.2.1.md).

Each selected desktop source is owned by a fixed hidden capture document with a separate nonpersistent session, no preload, Node, IPC, navigation or network access. Its one-shot selector enforces the exact chosen source and rejects audio. The dashboard denies direct modern and legacy desktop media requests and receives only bounded decoded JPEG preview packets with the original timestamp and an opaque connection token. Privacy masks remain on analysis images; source dimensions retain native geometry. Stop invalidates pending starts and destroys capture owners. A controlled native-window result does not establish successful capture of the user's monitors or mixed-DPI desktop; those still require a user retry and hardware acceptance evidence. The [v0.2 ledger](../.omx/logs/implementation-v0.2.md) preserves the prior layout and tray checks.

Earlier pane layout, docking, resizing and live-source continuity checks are recorded in the [v0.2.2 implementation ledger](../.omx/logs/implementation-v0.2.2.md). The [v0.2.3 implementation ledger](../.omx/logs/implementation-v0.2.3.md) preserves the flat-workspace, default reflow and Reset/navigation checks. The [v0.2.4 implementation ledger](../.omx/logs/implementation-v0.2.4.md) preserves that version's pane sizing and local evidence; those changes are included in v0.3.0. It does not confirm a separate v0.2.4 GitHub release.

The earlier [v0.1 ledger](../.omx/logs/implementation-v0.1.md) preserves the first build's accepted checks. Mock responses and synthetic sources do not establish personal monitor capture, actual camera negotiation, native inputs, mixed-DPI placement, sleep/lock behavior or sustained performance. The separate direct model tests establish only the synthetic recognition and latency described above.

Not implemented in v0.3.0: Bionic MCP pairing or embedded UI, automatic host model-picker synchronization, cloud providers, voice, IP camera, persisted encrypted setup/history, automatic source restoration, broker integration, unattended action grants, general shell execution, auto-update and signed distribution. The local workflows do not include NVIDIA VSS deployment, its GPU infrastructure or API compatibility, or Axelera Metis acceleration. Background mode depends on an interactive desktop and an available system tray. Chart conversation can describe sampled pixels but exact trading rules require the future structured-data adapter. Implementation issues remain open until their complete gate is evidenced.
