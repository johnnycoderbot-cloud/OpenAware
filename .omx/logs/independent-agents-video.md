# Independent agents and video source handoff

Date: 2026-10-03. Status: local verification complete; public delivery gates pending. [Execution plan](../plans/independent-agents-video.md).

Baseline v0.3.3 is clean and publicly delivered. The user authorized independent agent connections/feed assignments, PC videos and web links including YouTube, Facebook, TikTok, Instagram and X. Native workers own runtime, capture and UI slices. No personal feed or platform account is used for validation.

## Implemented scope

- Shared catalog of sixteen sources; four independent agents with zero to four assigned feeds each. Each agent owns its binding/probe, queue, conversation, rules, temporal samples, captions and summaries. Capture is shared; only assigned pixels reach an engine. Default Agent 1 is an operator; added seats are unbound and unassigned. Explicit Feeds editing ends Agent 1's initial automatic assignment behavior.
- Native video picker, direct HTTP(S) media and isolated web-page players. Source metadata uses opaque references. The typed URL form handles the entered link while preparing it; registrations do not expose raw paths/URLs in source/frame metadata or model request envelopes. Actual playback frames enter the existing mask/freshness pipeline. Open player provides playback controls or site sign-in.
- Active operator, agent revision, assignment, verified binding and exact pending-plan identity are checked before native review and effects. Action cleanup cancels the originating agent, even after switching. Video sources cannot target native input. The opt-in CLI retains its restricted command surface and redacted status metadata.
- Compact independent desk seats and source controls preserve the flat workspace. Start/Pause are per agent; Stop releases all owners and invalidates all engines. Service failure and immediate Stop cancel pending summaries across the active alias and every agent.

## Reproduced defects and corrections

Cancelled model probes could leave an agent permanently Checking; shared catalog image retention duplicated buffers; a failed duplicate source admission could remove an existing video registration; awaited web-page captures could receive a newer timestamp than the captured evidence; native action cleanup could cancel a different selected agent's plan. Scoped regressions and cross-reviews verify the repairs.

A hidden direct/file decoder could play to completion without video callbacks. A bounded discarded one-pixel capture keeps its compositor awake; evidence still comes only from timestamped decoded video callbacks. Two consecutive enhanced video fixture runs passed after that repair. The full integration run exposed a finite-video test race after Open player and a compact-layout overflow. The fixture now pauses actual decoded playback during UI checks, then resumes to prove natural completion/reconnect; two unchanged runs passed (42.6s and 34.0s). Compact navigation now uses accessible named icons below 1100px. Actual geometry and focused workflows verify no horizontal overflow at 600/800/1024 with a long agent name and active watching.

Final review also reproduced a same-agent race: cleanup from an old native review could cancel a superseding goal. Cleanup now supplies both the agent ID and the reviewed plan ID, and the service atomically ignores a mismatched plan. Ordinary user cancellation still cancels current planning work. A held superseding-goal regression verifies the distinction.

Packaged testing found an intermittent paused-owner loss. A deterministic regression held a real native compositor image response for six seconds and reproduced source destruction under the auxiliary five-second wake timeout. That discarded wake now retains one serial operation until completion or Stop, while real startup/poll/page evidence deadlines remain unchanged. Paused pixels keep their original timestamps; late helper completion cannot revive a stopped owner or affect its replacement.

Native diagnostics then isolated a separate reconnect defect: a newly decoded frame arrived with its original timestamp one millisecond ahead of the main process's post-receipt clock. The strict zero-skew validator rejected it and closed the owner without an EOF, media error or renderer crash. The native preview validator now accepts at most 1000ms of clock skew, matching the renderer, without changing timestamps or stale/order/replay/geometry/JPEG bounds. Service inference retains its stricter 250ms admission. Boundary tests accept +1ms/+1000ms unchanged and reject +1001ms; an independent review approved the exact repair. Two serial video workflows passed against the final rebuilt package (53.6s and 51.2s).
