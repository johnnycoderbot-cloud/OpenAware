# OpenAware foundation execution plan

Date: 2026-10-02. Status: planning/repository delivery. [Foundation requirements](foundation-requirements.md) are the authority for the current task.

## Authorized outcome

User request: “Plan out every detail create a github for it too.” Repository choice: “OpenAware — public, MIT.”

Deliver a public MIT repository with product/UX behavior, architecture/contracts, sourced integration evidence, privacy/action boundaries, explicit risks, a concept visual, development backlog, testing/release strategy, and contributor guidance. There is no application implementation, live source capture, cloud-provider connection, personal credential collection, computer-action execution, or broker order in this foundation task.

2. Verify current primary documentation for LM Studio/Bionic, capture/model/provider capabilities; mark untested host integration explicitly.
3. Produce the product, UX, architecture, contracts, privacy, and decision documents in parallel with named file ownership.
4. Build execution backlog OA-001..OA-026 and map every product requirement to at least one slice.
5. Review cross-document defaults and model/source/action boundaries; resolve inconsistent paths and unsupported promises.
6. Validate JSON, dependency graph, requirement coverage, relative links, MIT/status metadata, and absence of personal/private artifacts.
7. Publish the authorized public repository and backlog without connecting any feeds or accounts.
8. Verify remote repository, default branch/head, visibility/license, issue body details, and linked artifacts.
9. Record handoffs/reviews and complete foundation status only when the required artifacts and publication are evidenced.

The runtime application path begins later with OA-001 evidence. The current repository does not pass G0-G5 merely because those gates are written.

## Foundation acceptance

- Every stable requirement has a roadmap/slice reference and measurable acceptance.
- Every slice includes files, dependencies, requirements, acceptance, verification, deliverable, effort assumptions, and an exit gate.
- Each initial slice has bounded 30-60 minute work units; later work separates discovery/review from unestimated implementation.
- Proposed reference defaults agree across docs: four sources, 1280x720/15 fps requested preview, actual negotiation displayed, 2-second eligibility, one local inference, newest-frame queues, 15-second stale default, at most one foreground turn before an eligible background turn, no every-frame interpretation claim. Stop invalidation is immediate; reference acknowledgement/acquisition-cessation target is 1 second and owned-resource teardown target is 2 seconds.
- Retention agrees: memory-only observations/events/conversation cap 1,000 events/16 MiB; explicit encrypted local-history opt-in defaults seven days/100 MiB; frame retention separate and off; structural configuration may persist.
- Bionic picker synchronization, dashboard embedding, and unsolicited alerts stay unverified until independent spikes pass; standalone/manual-binding/local-alert fallbacks exist. An unavailable bridge can explicitly defer and does not block standalone alpha. Images and summaries require route/retention grants; strict-local sources deny unknown host routes.
- Numerical trading conditions require structured timestamped data; paper proposals contain no live-order route.
- Actual actions and live orders remain separately gated and authorized.
- Public repository includes no credentials, personal feeds, machine-specific private files, or claims of a functioning app.
- Publication evidence is independently verified and recorded by the coordinator.

See [foundation verification](foundation-verification.md) for performed foundation checks and pending implementation gates.
